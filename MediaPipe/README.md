# MediaPipe4VRChat

Проект використовує веб-камеру та бібліотеку MediaPipe Pose для відстеження рухів верхньої частини тіла користувача. Він перетворює обертання тулуба (yaw) та нахил (pitch) в команди керування поглядом аватара у VRChat.

## Як це працює

1.  **Захоплення відео:** Програма захоплює відео з веб-камери за допомогою OpenCV.
2.  **Виявлення пози:** Модель MediaPipe Pose обробляє кожен кадр для виявлення ключових точок тіла (плечі, стегна, ніс).
3.  **Адаптація:** Необроблені дані MediaPipe перетворюються на спрощений набір точок тіла.
4.  **Відстеження:** Програма обчислює орієнтацію тулуба (кути yaw та pitch) на основі положення плечей та вектора від плечей до носа (для нахилу), з урахуванням коригування чутливості.
5.  **Калібрування:** Користувач може встановити нейтральну позицію "T-pose" або стоячи. Система обчислює всі наступні рухи відносно цієї відкаліброваної нейтральної пози.
6.  **Логіка керування:** Відносні кути проходять фільтри (згладжування, мертві зони, пороги) та масштабування налаштуваннями з `config.json`, і перетворюються на значення `LookHorizontal` та `LookVertical`, які розуміє VRChat.
7.  **Передача OSC:** Кінцеві значення надсилаються до VRChat через мережу за допомогою протоколу OSC.

Яка поза яку команду дає:

*   голова повернута або зміщена **вправо** відносно плечей → погляд аватара вправо; **вліво** → вліво;
*   підборіддя опущене до грудей → погляд униз; підняте підборіддя (або голова відхилена назад) → погляд угору;
*   права кисть піднята в кадр так, щоб камера її впізнала → «хоп»; опущена чи схована → розтиснути;
*   ліва кисть піднята в кадр → «використати» предмет, на який дивиться аватар. Один підйом — одна дія (повторить можна, опустивши й знову піднявши руку). Що саме це означає, вирішує світ: у одному предмет відлетить, в іншому — натисне кнопку чи спрацює як постріл;
*   погляд керується лише після калібрування клавішею `1`; обидва жести рук працюють незалежно від калібрування, одразу після запуску.

Як саме метрики перетворюються на значення `[-1 ; +1]`, які є адреси OSC, транспорт, пороги `GrabRight` і невикористані методи — у [Project.md](file:///C:/Users/User/Yoga/NonVR4VRChat/MediaPipe/Project.md), ЧАСТИНА 3. Там же підрозділ 3.6 про дзеркалювання: напрямок «вправо → додатнє значення» залежить від того, чи драйвер камери дзеркалить зображення апаратно, тож при першому запуску обидва напрямки варто перевірити на собі.

Додаток показує відео з камери в реальному часі, на якому залишилось лише те, що потрібно людині: зелені точки там, де MediaPipe бачить ніс, плечі та кисті, попередження вгорі (`Pose not detected`, `NO CALIBRATION - PRESS 1`), індикатор `CALIBRATION...` під час калібрування та рядок-підказка про клавіші внизу. Технічні значення (FPS, метрики, `LookHorizontal`/`LookVertical`) на екран не виводяться — за потреби дивись консоль з `debug: true`. Керування здійснюється за допомогою гарячих клавіш для калібрування та скидання відстеження.

## Конфігурація (`config.json`)

Параметри керування зберігаються у файлі [config.json](file:///C:/Users/User/Yoga/NonVR4VRChat/MediaPipe/config.json):


### Опис параметрів:
*   `debug`: вивід у консоль під час роботи:
    *   `true` — видно кожну команду, яка пішла у VRChat, разом із її значенням (`OSC: /input/LookHorizontal = 0.523`), і події руки (`Action: Grab` / `Action: Drop`).
    *   `false` — програма мовчить; лишаються лише повідомлення про калібрування (`Calibration completed.`) та скидання (`Reset.`).

    Значення зчитується один раз на старті, тому після зміни `config.json` програму треба перезапустити. Команди погляду надсилаються на кожному кадрі, тож у консоль вони потрапляють лише коли значення змінилось помітно — інакше вивід заповнював би екран тридцятьма рядками за секунду.

*   `camera_index`: номер камери, з якої програма бере відео:
    *   `0` — перша камера, яку бачить система (типово), `1`, `2`, ... — наступні.
    *   Якщо під `0` відкривається не те, що треба (віртуальна камера, камера телефона як веб-камера тощо), міняй по одному й перезапускай програму.
    *   Значення зчитується один раз на старті, тому після зміни потрібен перезапуск.
    *   Немає ключа, пошкоджений файл або не число — програма бере `0` і пише про це в консоль, а не мовчки.
    *   Якщо обрана камера не дає відео, вікно не з'явиться, але програма не висить мовчки: кожні 5 секунд у консоль пишеться, що саме не так — `Камера 1 не відкрилась` (такого індексу немає) або `Камера 1 кадрів не дає` (пристрій є, але не стрімить — часто його зайняла інша програма). Цикл не переривається, тому досить під'єднати камеру або виправити `camera_index` і перезапустити.

*   `velocity_type`: режим керування швидкістю аватара:
    *   `var` — змінна швидкість (пропорційна куту відхилення тулуба, використовує класичну квадратичну криву).
    *   `const` — постійна швидкість (активується при перевищенні заданого порогу).

    *Увага:* у поточній версії програма читає лише секцію `var_settings`, тому `velocity_type: "const"` і вся секція `const_settings` ні на що не впливають — фактично завжди працює режим `var`.

 1. "horizontal_sensitivity_pct" (Чутливість у відсотках)
       * Призначення: Це прямий множник для вашого фізичного руху. Він визначає, наскільки сильно початковий зсув вашої метрики (Yaw Metric) буде посилений.
       * Аналогія: Уявіть це як "підсилювач" або "коефіцієнт передачі". Більший відсоток означає, що навіть невеликий поворот плечей буде значно посилений, що призведе до швидшого набору швидкості повороту аватара.
       * Працює так: scaled_yaw = (Ваш поворот плечей) * (horizontal_sensitivity_pct перетворений на множник).

   2. "max_horizontal_metric" (Максимальне значення метрики)
       * Призначення: Це поріг, який визначає, яке значення посиленої метрики (scaled_yaw) вважається "повним поворотом" (тобто, коли аватар досягає максимальної швидкості повороту в VRChat). Це використовується для нормалізації значення до діапазону від -1 до 1.
       * Аналогія: Уявіть це як "максимальна швидкість", яку ви можете досягти, або "межа діапазону". Якщо ваш scaled_yaw досягне max_horizontal_metric, аватар повертатиметься на повній швидкості. Якщо ваш scaled_yaw менший за це значення, швидкість повороту буде пропорційно меншою.
       * Працює так: Швидкість повороту = scaled_yaw / max_horizontal_metric.

3. "horizontal_threshold_metric" (За замовчуванням: 0.02)
       * Призначення: Це "мертва зона". Невеликі рухи плечей (нижче цього порогу) ігноруватимуться.
       * Як налаштовувати: Якщо аватар трохи дрейфує або сам повертається, коли ви стоїте нерухомо, збільшіть це значення, щоб розширити мертву зону та ігнорувати цей шум.
       
  Як вони працюють разом:
   * horizontal_sensitivity_pct контролює, як швидко ваша метрика yaw зростає.
   * max_horizontal_metric контролює, наскільки великою має стати ця метрика yaw, щоб аватар повернувся на повну швидкість.
   * horizontal_threshold_metric — мертва зона: якщо аватар повзе або сам повертається, коли ви стоїте нерухомо, збільшуйте це значення.

Вертикальні параметри (`vertical_sensitivity_pct`, `max_vertical_metric`, `vertical_threshold_metric`) працюють так само, але для нахилу вперед/назад, а `smooth` (від 0 до 1) задає інертність: чим менший, тим швидше аватар доганяє вашу позу.

*Загальне правило:* метрики рахуються з координат кадру без урахування глибини, тому фактична чутливість залежить від дистанції до камери та вашого зросту. Переставили або підняли камеру — налаштуйте `config.json` повторно.

## Клавіші

*   `1` - Калібрування
*   `R` - Скидання
*   `ESC` - Вихід

Клавіші працюють лише у вікні програми (воно має бути активним) і дублюються у підказці внизу цього вікна, тож запам'ятовувати нічого не треба.

Калібрування триває 4 секунди: натисніть `1`, почуєте зворотний відлік і просто стойте нерухомо в тій позі, яку хочете вважати нейтральною. `R` скидає калібрування — погляд перестає керуватися, доки знову не натиснете `1`. Якщо під час калібрування камера перестала бачити позу, сесія не завершиться: натисніть `R` і потім `1` ще раз.

Інтерфейс керування, сесію калібрування, відомі нюанси поведінки і те, що саме перевіряють тести, описано в [Project.md](file:///C:/Users/User/Yoga/NonVR4VRChat/MediaPipe/Project.md) — ЧАСТИНА 4.


### Особливості встановлення програми в ОС Windows

1) Завантажити Python 3.10
https://www.python.org/ftp/python/3.10.10/python-3.10.10-amd64.exe

2) знаходячись у терміналі GitBash, клонувати репозиторій:
gi clone https://github.com/oleksandrblazhko/NonVR4VRChat.git

3) перейти до каталогу NonVR4VRChat:
cd NonVR4VRChat

4) Створити окреме віртуальне середовище з версією 3.10:
py -3.10 -m venv .venv

5) Активізувати середовище:
. .venv/Scripts/activate

6) Встановити бібліотеки:
- py -m pip install --upgrade pip
- py -m pip install -r requirements.txt

7) запустити програму:
py MediaPipe/main.py
або
.venv/Scripts/python.exe MediaPipe/main.py

8) після роботи деактивізувати (за бажанням):
deactivate


### Перевірка кнопок у VRChat

Якщо треба з'ясувати, чи спрацьовує якась OSC-команда у VRChat (наприклад `UseRight`) і як саме — є окрема програма:
```
python osc_use_probe.py --dry-run          # спочатку подивитись, що піде
python osc_use_probe.py                    # 5 коротких натискань UseRight
python osc_use_probe.py --hold 3           # те саме, але тримати кнопку 3 секунди
```
Вона сама рахує зворотний відлік на старті — за цей час устигнеш перемкнути вікно VRChat, бо без активного вікна команди рук не працюють. Параметри, умови та підказки описані в [Project.md](./MediaPipe/Project.md), підрозділ 3.8.
